# Historical design notes

This document records implementation decisions. Use the [README](../../README.md) for current setup and operations.
Single owner, Twilio → ElevenLabs voice agent, and an HTTPS tunnel to a localhost bridge.

Expose only initiation, passphrase verification, list/status, and follow-up messaging. Reads require authentication too. Spoken passphrase and allowlisted caller number replace OTP. Caller ID is spoofable and the passphrase can appear in provider transcripts: accepted limitations.

Trust boundary: authenticated ElevenLabs initiation webhook (dedicated header secret, never shared with tools) creates an opaque, random call capability in a secret__ dynamic variable. Tool headers carry that capability. Caller/call IDs are never accepted in tool arguments. Twilio REST lookup corroborates inbound From/To/account/SID and live status before every tool request. Network failures deny access. Initiation replay never resets attempts or lifetime. Call capability expires after 15 minutes; Twilio live lookup also rejects ended calls (subject to provider propagation). Three failures per call and ten globally per 15 minutes. Restart revokes calls.

Each explicitly loaded Pi extension hosts HTTP on a Unix socket in a mode-0700 directory, socket mode 0600. Local same-UID processes are trusted (not a sandbox). Discovery is bounded; no tmux screen scraping or keystrokes. Pi session UUID plus process instance identify targets. Heartbeat/status are bounded; stale targets reject messages. Follow-ups use public sendUserMessage API. Extension-owned bounded ID ledger avoids duplicates for process lifetime, rejecting conflicts/full ledger. Never claim ingestion, acceptance, queuing or acted: receipt is submitted_unconfirmed after a void public API return, or indeterminate after a synchronous exception, always acted:false. Pi catches async submission rejections separately, so neither receipt is a delivery acknowledgment. Both outcomes remain deduplicated without automatic retry. Always explicitly pass deliverAs:'followUp', including initially idle sessions.

## Revised user requirement: automatic conversation excerpts
The initial manual-summary-only implementation did not satisfy the revised requirement. The owner now explicitly authorizes bounded recent user and visible assistant text being shared with ElevenLabs. Expose up to 8 completed messages, 800 characters each, role/timestamp/truncation metadata, loaded only from the active Pi branch and updated automatically at message_end. Exclude all other roles and non-text blocks (especially tool calls/results and reasoning). Refresh on session start, tree navigation and compaction to avoid abandoned-branch leakage. Keep manual summaries optional. Authentication exchanges remain exclusively in /verify and are never routed into Pi; ordinary phone work instructions are included. No heuristic secret detection is promised. Authentication, call binding, and stale-status checks remain required.
